1. INTRODUCTION                                  *simplemarkdown-introduction*

SimpleMarkdown renders a Markdown buffer into a second Vim window, laid out
and styled as prose rather than shown as source.  Headings get rules, lists
get bullets, quotes get bars, tables get boxes with aligned columns, and
fenced code blocks are drawn in a labelled frame with syntax highlighting.

No browser, no HTTP server, no external viewer.  The preview is an ordinary
Vim buffer, so it works over SSH, inside tmux, and in any terminal Vim runs
in — and the cursor in the source follows the cursor in the preview.

The layout work happens in a Rust daemon: CommonMark parsing with
pulldown-cmark, display-width-correct line breaking with unicode-width
(so CJK text wraps at the right column), and syntax highlighting with syntect.
The daemon returns rows plus text-property spans; Vim only has to place them.

==============================================================================
2. INSTALLATION                                  *simplemarkdown-installation*

With vim-plug: >

    Plug 'beamiter/simplemarkdown', {'do': './install.sh'}
<
The plugin needs its backend compiled once: >

    cd ~/.vim/plugged/simplemarkdown
    ./install.sh
<
On Windows, run `install.ps1` instead.  `install.sh` builds with `--locked`,
runs the binary's `--self-test`, and only then moves it into `lib/`, so a
build that cannot lay out its own documentation never replaces a working one.

The plugin finds the backend by searching, in order: |g:simplemarkdown_daemon_path|,
`lib/` under every 'runtimepath' entry, `target/release` and `target/debug`
under the same (a developer convenience), and finally $PATH.

==============================================================================
3. USAGE                                                *simplemarkdown-usage*

Open a Markdown file and run: >

    :SimpleMarkdown
<
A preview window opens beside it and re-renders as you type, debounced by
|g:simplemarkdown_debounce| milliseconds.  Move the cursor in the source and
the preview scrolls to the matching row; the mapping is per source line, not
per block, so a cursor in the middle of a long paragraph lands in the middle
of the rendered paragraph.

There is one preview per tab page.  Switching to another Markdown buffer in
the same tab re-points the existing preview at it rather than opening a
second one.

4. COMMANDS                                          *simplemarkdown-commands*

                                                              *:SimpleMarkdown*
:SimpleMarkdown         Toggle the preview for the current tab page.

                                                          *:SimpleMarkdownOpen*
:SimpleMarkdownOpen     Open the preview.  Does nothing if one is already open.

                                                         *:SimpleMarkdownClose*
:SimpleMarkdownClose    Close this tab page's preview.
:SimpleMarkdownClose!   Close every in-Vim preview without visiting its tab.
                        Browser preview servers are unaffected.

                                                       *:SimpleMarkdownRefresh*
:SimpleMarkdownRefresh[!]
                        Re-render now, skipping the debounce. Without [!],
                        refresh every tab previewing the current source; with
                        [!], refresh every open preview. Useful after an edit
                        made by a plugin, which may not fire |TextChanged|, or
                        after changing a global renderer option.

                                                         *:SimpleMarkdownFocus*
:SimpleMarkdownFocus    Move the cursor into the preview window, opening one
                        first if needed.

                                                           *:SimpleMarkdownToc*
:SimpleMarkdownToc      Show the document's headings in a popup menu; choosing
                        one moves to it.  With a preview open both windows go
                        there; with no preview the outline is asked of the
                        backend directly and only this cursor moves — asking
                        what is in a document does not open a window.  Falls
                        back to the location list when +popupwin is missing.

                                                  *:SimpleMarkdownToggleTask*
:SimpleMarkdownToggleTask
                        Check or uncheck the task under the cursor. From the
                        preview it follows the exact preview-to-source mapping;
                        from the source it acts on the current line. Nested,
                        ordered, and block-quoted task items are supported. A
                        preview map is valid only for the exact source revision
                        it rendered: a stale action is refused and immediately
                        refreshed. Every tab previewing that source refreshes
                        after the edit.

                                                        *:SimpleMarkdownFollow*
:SimpleMarkdownFollow   Follow the link under the cursor.  In the preview that
                        is what `gx` does; in the Markdown source the link is
                        found by pattern — inline, reference, autolink or bare
                        URL — so no preview window has to be open: >

                            autocmd FileType markdown
                              \ nmap <buffer> gf <Plug>(simplemarkdown-follow)
<
                        With the cursor on no link the line's leftmost link is
                        taken, which is what pressing the key on a line with one
                        link means.  See |simplemarkdown-links|.

                                                   *:SimpleMarkdownFormatTable*
:SimpleMarkdownFormatTable
                        Realign the GFM table the cursor is in.  Every column
                        is padded to its widest cell and the delimiter row is
                        rebuilt from the alignments it declares, so `|:-|` and
                        `| :--- |` come out the same.  A row short of a cell is
                        padded rather than truncated: a formatter should not
                        delete text.  Cell contents are moved, never reflowed,
                        so the whole change is whitespace and `git diff -w` of
                        it is empty.

                        How many columns the table has is the delimiter row's
                        to declare, and that is not changed either.  A row
                        carrying a cell past the last declared column keeps it,
                        unpadded, on the end of its row: GFM was already not
                        rendering it, and widening the table to make it a
                        column would make it appear — an edit to what the
                        document says, which this command does not make.  The
                        row is still a `ragged-table-row` to
                        |:SimpleMarkdownLint| afterwards, because it still is
                        one.

                        Column widths are display columns, measured by the
                        backend with the same tables the preview is laid out
                        with.  That is the point of asking it: a Vimscript
                        aligner measures with |strdisplaywidth()|, which
                        answers for the terminal it is running in rather than
                        for the file, so a table of CJK or emoji cells lines up
                        for its author and for nobody else.

                        Which lines are the table is decided by the parser, not
                        by a pattern: a `|` inside a fenced code block is not a
                        table row, and a table inside a block quote keeps its
                        `> `.  Only the table's own lines are rewritten, in one
                        undo step.

                        Run it in the Markdown source — it edits the document,
                        so the preview refuses it.  With the cursor outside any
                        table it says so and changes nothing.  Needs a backend
                        advertising the `format` capability: after updating the
                        plugin, run `./install.sh` and |:SimpleMarkdownRestart|.

                                                       *:SimpleMarkdownPromote*
                                                        *:SimpleMarkdownDemote*
:[range]SimpleMarkdownPromote
:[range]SimpleMarkdownDemote
                        Move heading levels one step shallower or deeper: `##`
                        becomes `#` or `###`.

                        With no range — the usual case — the whole section the
                        cursor is in moves: the heading at or above the cursor
                        and every heading nested under it, so demoting a chapter
                        takes its subsections with it and the document keeps the
                        tree it had.  With a range of more than one line exactly
                        the headings inside it move and nothing else.  (A
                        one-line range is what a bare command gives, so it keeps
                        the section meaning.)

                        A setext heading stays one where it can: its underline
                        changes between `=` and `-`.  There is no setext H3, so
                        demoting an H2 past it rewrites the two lines as one
                        `### heading`.  ATX headings keep their text, their
                        indent and their trailing `##`.

                        Refused whole, naming the heading, when any heading it
                        would move would pass H1 or H6 — half a shift leaves a
                        document restructured in a way nothing records.

                        What is a heading is decided by the parser: a `#` at the
                        start of a line in a fenced shell block is a comment, and
                        a setext underline makes a heading of a line with no `#`
                        on it at all.  Run it in the Markdown source — it edits
                        the document, so the preview refuses it.  Needs a backend
                        advertising the `edit` capability: after updating the
                        plugin, run `./install.sh` and |:SimpleMarkdownRestart|.

                                                      *:SimpleMarkdownRenumber*
:[range]SimpleMarkdownRenumber
                        Renumber the ordered lists the range touches, from the
                        number each list declares.  A list written `1.` `1.` `1.`
                        — which is what GFM renders as 1, 2, 3 — becomes `1.`
                        `2.` `3.`; one starting at `5)` stays starting at `5)`
                        and keeps its `)`.  Nested lists are numbered on their
                        own, bullets are left alone, and everything after the
                        marker is untouched.

                        With no range the list the cursor is in is renumbered,
                        including any list nested inside it.  `1.` lines inside a
                        fenced code block are a code sample, not a list.

                                                          *:SimpleMarkdownLint*
:SimpleMarkdownLint     Check the document and put what is wrong with it in the
                        |location-list|, opening it when there is anything to
                        show and closing it when there is not.  `W` entries are
                        something a reader will notice; `I` entries are advice.

                        The checks are the ones a parser can be certain about,
                        and deliberately not the fifty style rules markdownlint
                        ships: a linter opinionated about trailing spaces is one
                        people switch off, and once it is off the broken link
                        goes unreported too.  Nothing inside a fenced code block
                        is checked — a `# comment` in a shell sample is not a
                        heading and `[x](#nowhere)` in it is not a broken link.

                        Codes, as printed by `simplemarkdown-daemon --codes`: >

    broken-anchor       a #anchor link that matches no heading
    duplicate-anchor    two headings share one anchor
    empty-link          a link or image with no destination
    heading-skip        a heading level was skipped
    ragged-table-row    a table row has fewer or more cells than its header
    undefined-footnote  a footnote reference with no definition
    unused-footnote     a footnote definition nothing refers to
<
                        `broken-anchor` is only ever about an anchor in this
                        document: `other.md#section` names a heading in a file
                        the backend has never seen, and whether `./api.md`
                        exists at all is not checked.

                        Run it in the Markdown source.  Needs a backend
                        advertising the `lint` capability: after updating the
                        plugin, run `./install.sh` and |:SimpleMarkdownRestart|.
                        See |g:simplemarkdown_lint_on_write|.

                                                        *:SimpleMarkdownResize*
:SimpleMarkdownResize [{columns}]
                        Resize the preview window.  With no argument, re-apply
                        the configured width — handy after the terminal itself
                        has been resized.

                                                         *:SimpleMarkdownStyle*
:SimpleMarkdownStyle [unicode|ascii]
                        Switch decoration alphabets and re-render.  With no
                        argument, cycle to the next one, so the command is
                        worth binding to a single key.  See
                        |g:simplemarkdown_style|.

                                                       *:SimpleMarkdownRestart*
:SimpleMarkdownRestart  Restart the backend and clear the crash-loop breaker.

                                                        *:SimpleMarkdownHealth*
:SimpleMarkdownHealth   Report on the backend: where it was found, whether it
                        is running, the negotiated protocol version and
                        capabilities, restart counts and the last render time.
                        Two of those lines are the ones worth reading after an
                        update: whether the daemon's protocol and the plugin's
                        agree, and whether the installed binary is older than
                        the `src/` beside it.  Either says `./install.sh`.

                        It also lists every `g:` option that does not hold what
                        it says it holds, and every `g:simplemarkdown_`
                        variable that is not an option at all — the report
                        after a vimrc change, and the one place the corrections
                        made at load can still be seen.  See
                        |simplemarkdown-config-validation|.

                                                           *:SimpleMarkdownLog*
:SimpleMarkdownLog      Open the backend log in a scratch buffer.  The log is a
                        ring buffer that is always recording, so the interesting
                        startup and crash entries are there even if
                        |g:simplemarkdown_debug| was off at the time.

                                                         *:SimpleMarkdownDebug*
:SimpleMarkdownDebug    Echo a dictionary of internal state, including how many
                        of the recent renders were applied as patches rather
                        than as whole documents.  A patch that failed one of the
                        render checksums counts as a whole document, not as a
                        patch: resynchronising is what it cost.

The commands below drive the external preview — a browser, served by `omd`,
alongside the in-Vim one rather than instead of it.  See
|simplemarkdown-external|.

                                                      *:SimpleMarkdownExternal*
:SimpleMarkdownExternal Toggle the browser preview for this buffer.

                                                  *:SimpleMarkdownExternalOpen*
:SimpleMarkdownExternalOpen
                        Start `omd` for this buffer and open the browser at it.
                        If one is already serving this buffer, just re-open the
                        browser there.

                                                 *:SimpleMarkdownExternalClose*
:SimpleMarkdownExternalClose[!]
                        Stop this buffer's server.  With `!`, stop every one.

                                                *:SimpleMarkdownExternalStatic*
:SimpleMarkdownExternalStatic
                        Render once to a temporary HTML file and open it, with
                        no server and no live reload.

5. MAPPINGS                                          *simplemarkdown-mappings*

Global, installed only if the key is still free and
|g:simplemarkdown_set_default_mapping| is on: >

    <leader>md      toggle the preview
<
Plugs, for your own bindings: >

    <Plug>(simplemarkdown-toggle)
    <Plug>(simplemarkdown-focus)
    <Plug>(simplemarkdown-toc)
    <Plug>(simplemarkdown-toggle-task)
    <Plug>(simplemarkdown-follow)
    <Plug>(simplemarkdown-format-table)
    <Plug>(simplemarkdown-promote)          also in Visual mode
    <Plug>(simplemarkdown-demote)           also in Visual mode
    <Plug>(simplemarkdown-renumber)         also in Visual mode
    <Plug>(simplemarkdown-lint)
    <Plug>(simplemarkdown-next-heading)
    <Plug>(simplemarkdown-prev-heading)
    <Plug>(simplemarkdown-external)
    <Plug>(simplemarkdown-preview-close)
    <Plug>(simplemarkdown-preview-refresh)
    <Plug>(simplemarkdown-preview-activate)
    <Plug>(simplemarkdown-preview-help)
<
Inside the preview window, unless |g:simplemarkdown_default_mappings| is off: >

    q       close the preview
    r       re-render this document in every tab now
    <CR>    follow the link on this row; with no link, jump the source window
            to the line this row came from
    gx      follow the link on this row
    gO      show the table of contents
    x       check/uncheck the task on this row in the Markdown source
    ]]      next heading
    [[      previous heading
    g?      show this list, with whatever keys are actually in force
<
Each of those is a buffer-local |:nmap| onto the corresponding <Plug>, so any
one of them can be moved or dropped on its own — see
|g:simplemarkdown_preview_mappings|.

`<CR>` and `gx` resolve a link the same way: the one under the cursor, or —
when the cursor is not on one — the row's leftmost link.

`]]` and `[[` work in a Markdown source buffer as well, where they move that
buffer's cursor between headings.  Nothing binds them there by default; bind
`<Plug>(simplemarkdown-next-heading)` and `<Plug>(simplemarkdown-prev-heading)`
if you want them: >

    autocmd FileType markdown
      \ nmap <buffer> ]] <Plug>(simplemarkdown-next-heading)
    autocmd FileType markdown
      \ nmap <buffer> [[ <Plug>(simplemarkdown-prev-heading)
<

                                                        *simplemarkdown-links*
A link to `http:`, `https:`, `ftp:` or `mailto:` is handed to
`netrw#BrowseX()`, or to `xdg-open`/`open` if netrw is not loaded.  A relative
link is resolved against the source file's directory and opened in the source
window.

A `#anchor`, alone or after a file name, is matched against GitHub's heading
slug: the heading lower-cased, with everything that is not a letter, digit,
`_` or `-` removed and each remaining space turned into `-`, so `## Notes:
part one!` answers to `#notes-part-one`.  A heading repeated in one document
is numbered as GitHub numbers it, `#notes`, `#notes-1`, `#notes-2`.  A link
that matches no slug falls back to matching the heading's words, which is what
this did before slugs existed.  `other.md#section` opens the file and then
moves to that section; an anchor that names no heading says so and stays put.

Following a link is not limited to the preview window — see
|:SimpleMarkdownFollow| for the source-buffer side of it.

6. CONFIGURATION                                *simplemarkdown-configuration*

                                             *simplemarkdown-config-validation*
Every option below has a type, and each numeric one a range.  A value outside
either is corrected rather than obeyed: a number is clamped into its range,
anything else falls back to the documented default, and an entry of the wrong
type is dropped from a list or a dictionary.  Refusing instead would be worse
than it sounds — the render options are serialised into JSON that the daemon
deserialises into typed fields, so a `'4'` where a 4 was meant is a rejected
request and, from where you are sitting, a preview that stops updating.

The check runs twice.  Once when the plugin loads, which is where a documented
default comes from; and again on every read, which is what covers a `:let` from
a later `:source`, a modeline or a |FileType| autocommand — none of which the
load-time pass can see.

Nothing is corrected quietly.  |:SimpleMarkdownHealth| lists every option that
had to be changed, including the ones changed at load, where `g:` now holds the
corrected value and the mistake would otherwise have left nothing to find it
by; and the first use of the backend in a session says the same list once — not
at load, where a message is scrolled away by whatever loads next, and not on
every render either.  A `g:simplemarkdown_` variable that is not an option at
all is reported too, named alongside the option it is closest to when one is
close enough to be a slip: a misspelt option name is otherwise perfectly
silent, because nothing ever reads it.

Three functions expose that to a vimrc that wants to ask.

                                                     *simplemarkdown#Setting()*
simplemarkdown#Setting({name})
        The validated value of one option — exactly what the plugin itself
        would use for it, whatever `g:` currently holds.  Throws for a {name}
        that is not an option.

                                              *simplemarkdown#ValidateConfig()*
simplemarkdown#ValidateConfig()
        Everything wrong with the configuration right now, as a list of
        `[WARN]` and `[INFO]` lines — the same ones |:SimpleMarkdownHealth|
        shows.  Empty when there is nothing to say.

                                                *simplemarkdown#SettingNames()*
simplemarkdown#SettingNames()
        Every option name.  The same set this section documents: the test
        suite holds the two against each other, so an option implemented and
        not documented, or documented and not implemented, fails the build.

                                                       *g:simplemarkdown_width*
Preview window width in columns.  0 means half the Vim window.
Range: 0..400
Default: 0

                                                   *g:simplemarkdown_min_width*
Floor for the computed width.
Range: 12..400
Default: 30

                                              *g:simplemarkdown_max_text_width*
Cap on the text column inside the preview, independent of the window width.
Prose is hard to read at 200 columns even when the window offers them; set
this to 80 or 100 and the window can stay as wide as you like.  0 disables it.
Range: 0..400
Default: 0

                                                        *g:simplemarkdown_side*
`'right'` or `'left'`.
Default: 'right'

                                                    *g:simplemarkdown_debounce*
Milliseconds to wait after the last change before re-rendering.
Range: 0..5000
Default: 120

                                                       *g:simplemarkdown_style*
`'unicode'` draws with box-drawing characters and geometric bullets.
`'ascii'` draws with `+-|#*` only.  Use ASCII if your terminal treats
East Asian Ambiguous width characters as double width — box-drawing lives in
that category, and a terminal that renders it two columns wide will misalign
every table and code frame.
Default: 'unicode'

                                                      *g:simplemarkdown_syntax*
Syntax-highlight fenced code blocks.  Turning this off makes the first render
of a document containing code noticeably faster, because the syntax
definitions are then never loaded.
Default: 1

                                                        *g:simplemarkdown_wrap*
Reflow prose to the preview width.  With this off, each paragraph becomes one
long row and the preview scrolls horizontally.
Default: 1

                                                   *g:simplemarkdown_code_wrap*
Wrap over-long code lines onto a continuation row marked with `⤷`.  With this
off they are clipped at the frame edge and marked with `›`.
Default: 1

                                                   *g:simplemarkdown_show_urls*
Append a link's or image's target after its text, dimmed: `docs (./x.md)`.
For an image this is often the only thing that says which file it is.
Default: 0

                                                   *g:simplemarkdown_link_hint*
While the cursor moves through the preview, echo the target of the link it is
on.  This answers "where does this go" without |g:simplemarkdown_show_urls|
spending a row on every URL in the document.
Default: 1

                                                *g:simplemarkdown_code_numbers*
Number the lines inside fenced code blocks.  The gutter comes out of the code's
own columns rather than widening the frame, so a narrow preview buys the
numbers with more wrapping — which is why this is off by default, and why it is
most useful in a wide window or when you are quoting line numbers to someone.
Default: 0

                                                 *g:simplemarkdown_table_zebra*
Tint every other table body row.  A row whose cells wrapped onto three lines is
one stripe, not three.  Off by default because it depends on your colour scheme
having a `CursorLine` that is visible but not loud; see
|SimpleMarkdownTableRowAlt| to point it somewhere else.
Default: 0

                                               *g:simplemarkdown_task_progress*
Close a task list of two or more checkboxes with a `2/5 done` line, at the
list's own indent.  A nested checklist summarises itself where it sits.
Default: 1

                                                *g:simplemarkdown_focus_block*
Wash the whole block the source cursor is in, rather than marking one preview
row with 'cursorline'.  A preview row is not a unit of anything — a paragraph
is six of them — so the row the cursor lands on says little about which block
you are editing.  See |SimpleMarkdownFocusBlock|.
Default: 1

                                                 *g:simplemarkdown_incremental*
Let the daemon answer a render with just the rows that changed.  Typing in a
paragraph then repaints two rows instead of the whole document.  Turning it off
makes every render a full one; the only reason to is to rule the patch path out
while diagnosing something.  |:SimpleMarkdownHealth| reports how many of the
recent renders went each way.
Default: 1

                                                 *g:simplemarkdown_frontmatter*
Render a YAML or TOML front-matter block as a labelled code frame.  With this
off, front matter is omitted from the preview entirely.
Default: 1

                                                   *g:simplemarkdown_tab_width*
Columns a tab expands to inside code blocks.
Range: 1..16
Default: 4

                                                 *g:simplemarkdown_sync_scroll*
Scroll the preview to follow the source cursor.
Default: 1

                                                   *g:simplemarkdown_sync_back*
Also move the source cursor when the cursor moves inside the preview.  Off by
default: it makes browsing the preview move the file you are editing.
Default: 0

                                                   *g:simplemarkdown_auto_open*
Open a preview automatically whenever a Markdown buffer is entered.
Default: 0

                                                  *g:simplemarkdown_auto_close*
Close the preview when the buffer it was previewing goes away and no other
Markdown buffer in the tab page can take over.
Default: 1

                                                   *g:simplemarkdown_filetypes*
Filetypes treated as Markdown.  A file with no filetype at all is still
previewed if its name ends in a Markdown extension.
Default: ['markdown', 'markdown.pandoc', 'pandoc', 'rmd', 'vimwiki',
          'ghmarkdown']

                                            *g:simplemarkdown_default_mappings*
Install the buffer-local mappings listed under |simplemarkdown-mappings|.
Default: 1

                                            *g:simplemarkdown_preview_mappings*
Per-key overrides for the preview window, keyed by action name: `close`,
`refresh`, `activate`, `open-link`, `toc`, `toggle-task`, `next-heading`,
`prev-heading`, `help`.  An empty string drops that one mapping and leaves the
rest alone, which used to mean turning all of them off: >

    " keep everything, but do not put `x` on task toggling
    let g:simplemarkdown_preview_mappings = {'toggle-task': ''}

    " and move `q` out of the way
    let g:simplemarkdown_preview_mappings = {'close': '<Leader>q'}
<
`g?` in the preview lists the keys that are actually in force, so it follows
whatever you set here.
Default: {}

                                        *g:simplemarkdown_set_default_mapping*
Install the global `<leader>md` mapping.
Default: 1

                                                 *g:simplemarkdown_daemon_path*
Explicit path to `simplemarkdown-daemon`, overriding the search.
Default: ''

                                                *g:simplemarkdown_auto_restart*
Restart the backend automatically if it dies, with exponential backoff and a
crash-loop breaker.
Default: 1

                                                     *g:simplemarkdown_folding*
Fold Markdown source buffers by heading.  Sets 'foldmethod' to `expr` on a
Markdown buffer, with a fold per section running from its heading to the line
before the next heading of the same level or shallower, so an H2 contains its
H3s.  The levels come from the backend's parse rather than from a pattern over
`^#`, which is what makes a `# comment` inside a fenced shell block stop being
a heading — the thing every Markdown foldexpr in the wild gets wrong.

The levels are cached per buffer and refreshed in the background after an edit;
while a refresh is in flight the previous levels stand, so folds do not flap
open on a keystroke.  When one lands it invalidates Vim's fold cache and
nothing else: a fold you closed by hand stays closed, and no other window on
the buffer has its folds opened around its cursor.  'foldlevel' is set to 99,
i.e. everything open: `zM` closes them all, `zR` opens them again.
Default: 0

                                              *g:simplemarkdown_lint_on_write*
Run |:SimpleMarkdownLint| on every write of a Markdown buffer, silently: the
location list is filled and nothing is opened, so `:lopen` (or `:lnext`) shows
what the last save found.  A save that grabs the screen is a save people stop
making, which is why the window is left alone.
Default: 0

                                                       *g:simplemarkdown_debug*
Echo backend log entries as they happen.  The log is recorded either way; see
|:SimpleMarkdownLog|.
Default: 0

The rest configure the external preview; none of them do anything unless a
|:SimpleMarkdownExternal| command is used.

                                                    *g:simplemarkdown_omd_path*
Explicit path to the `omd` binary.  Empty searches $PATH and then
`~/.cargo/bin`, which is where `cargo install` puts it and which a Vim started
from a desktop session frequently has not picked up.
Default: ''

                                                    *g:simplemarkdown_omd_host*
Address the server binds.  `'0.0.0.0'` makes the preview reachable from other
machines on the network; the browser is still pointed at the loopback address.
Default: '127.0.0.1'

                                                    *g:simplemarkdown_omd_port*
The first port tried.  A port already in use moves the search up rather than
failing, so several buffers can be previewed at once.
Range: 1024..65500
Default: 3030

                                                    *g:simplemarkdown_omd_args*
Extra arguments passed to `omd`, between the host/port flags and the filename.
Default: []

                                                 *g:simplemarkdown_omd_browser*
Open the browser when a server starts.  With this off the URL is echoed
instead, which is what you want over SSH with a forwarded port.
Default: 1

                                           *g:simplemarkdown_omd_browser_delay*
Milliseconds to wait before opening the browser, so it does not race the server
to the port and land on a "connection refused" page.
Range: 0..5000

8. SUPPORTED MARKDOWN                                *simplemarkdown-markdown*

CommonMark, plus the GitHub extensions that matter in practice:

    - ATX and Setext headings
    - paragraphs, hard breaks, thematic breaks
    - bullet, ordered and task lists, nested to any depth, tight and loose
    - block quotes, nested, and GFM alerts (`> [!NOTE]` and friends)
    - fenced and indented code blocks, with syntect highlighting
    - tables, with per-column alignment and automatic column fitting
    - links, autolinks, images, reference links
    - footnotes, numbered consistently between reference and definition
    - definition lists
    - strikethrough, superscript, subscript
    - inline and block HTML, shown as dimmed source
    - YAML and TOML front matter

Ordered list markers are right-aligned to the widest number in the list, so
`9.` and `10.` put their text in the same column.  Table columns that do not
all fit are shrunk in proportion to what they asked for, so one prose column
does not squeeze three short ones to nothing.

Not rendered: images (the alt text and a marker are shown instead), LaTeX
maths (shown verbatim as code), and Mermaid diagrams (shown as a code block).
A terminal cannot do better with any of them.

9. EXTERNAL PREVIEW                                  *simplemarkdown-external*

The in-Vim preview and the browser one answer different questions, so the
plugin offers both and neither replaces the other.

The buffer preview is for reading and navigating a document while you write
it: over SSH, inside tmux, with the two cursors tied together and the block
you are editing washed in the preview.  The browser preview is for seeing what
the document will actually look like — proportional type, images that are
images, and LaTeX that is typeset rather than shown as source.

The browser side is `omd`, a separate binary you install yourself: >

    cargo install omd
<
Nothing about it is linked into `simplemarkdown-daemon`.  omd pulls in a web
server, a file watcher and a clipboard stack, and none of that belongs in a
process whose whole job is to lay out rows of text.  The plugin only supervises
it: one server per source buffer, each on its own port, all of them stopped
when Vim exits or the buffer is wiped.

                                                 *simplemarkdown-external-save*
omd watches the file on disk, so the browser follows `:w` rather than every
keystroke.  That is the trade for not keeping a shadow copy of the buffer on
disk; the in-Vim preview is the one that updates as you type.

A buffer that has never been written has no file to watch and starts no server.

|:SimpleMarkdownHealth| reports whether omd was found and lists every URL
currently being served.

10. ARCHITECTURE                                 *simplemarkdown-architecture*

The plugin talks to `simplemarkdown-daemon` over JSON lines on stdin/stdout,
supervised by simplecore — the same daemon supervisor the rest of the simple*
suite uses.  simplecore owns process lifetime, generation-guarded callbacks,
exponential-backoff restarts, the crash-loop breaker and request/reply
correlation with timeouts.

A render request carries the whole buffer, the preview window's width, the
current options, and which preview window is asking.  The reply carries:

    - either every row, or — see below — just the ones that changed.  A row is
      its text, its text-property spans as [column, length, class] with 1-based
      byte columns, and the 1-based source line it came from
    - the table of contents, with both source line and preview row
    - every link, with its row, column, length and target
    - every top-level block, as its rendered extent and the source lines it
      came from, which is what lets the preview wash the block you are in

Vim groups the property spans by class and adds each group with one
|prop_add_list()| call.  A document with tens of thousands of spans therefore
costs about fifty calls, not tens of thousands.

                                              *simplemarkdown-incremental*
Most renders do not send the whole document at all.  The daemon remembers the
rows it last sent for a window and replies with the splice that turns them into
the new ones, found by trimming the common prefix and then the common suffix —
which is exactly the shape of an edit, since typing in a paragraph reflows that
paragraph and leaves everything above and below it identical.  A keystroke in a
five-thousand-row document then moves one row over the wire instead of five
thousand, and Vim repaints one row's properties instead of all of them.

Two rows count as the same row when they *look* the same.  The source line a
row came from is deliberately not part of that comparison: it moves on every
row below an inserted line while nothing on screen moves at all, and comparing
it left no common suffix for `Enter`, `o`, `dd` or any paste — half of all
editing — so those edits used to send the whole document.  The row → source map
is repaired instead by its own correction, which for an insertion or a deletion
is a single number ("everything from row N on moved by two") whatever the size
of the document.

The outline, the link table and the block index are sent only when they
change.  Each describes the whole document however little of it moved, so on a
one-word edit they were the reply and the patch was a rounding error beside
them — and Vim parses that JSON on the main thread on every keystroke.  Absent
means "keep what you have"; a preview that has thrown its copies away asks for
a full render, which always carries all three.

The reply carries two checksums, the row count and the sum of the source map,
because the rows and the map are spliced independently and a map that has
drifted while the text has not would otherwise stay invisible until it moved
the cursor — or an `x` — to the wrong line.  If either disagrees after a splice
Vim asks for a whole document rather than redrawing something already wrong.
|g:simplemarkdown_incremental| turns the whole mechanism off.

Three more details worth knowing if you are reading the source:

Renders are cancellable.  A keystroke burst queues one render per debounce
window; each new one cancels the last, both in Vim's pending-request table and
in the daemon, which drops the work before starting it.

A render is discarded if the window has been resized since it was requested.
Layout is width-specific; a reply for the old width would show a ragged right
edge until the next keystroke.  Discarding it also drops the session's claim to
be holding what the daemon last sent — the daemon computes the next patch
against exactly that — and asks for a whole document, so a resize costs one
extra round trip rather than a splice into the wrong rows.

The preview-to-source row map is bound to the source buffer's |changedtick|
and to the render generation that produced it. Editing through an older map
could target a different checkbox after lines were inserted, so preview `x`
fails closed and requests a fresh render instead. Source edits schedule every
preview session for that buffer, including sessions in other tab pages.

Fenced blocks are highlighted once and memoised on their content, so editing a
paragraph does not re-run syntect over every code block in the file.  Syntax
highlighting is the most expensive thing in a render by a wide margin, and it
is almost never what changed.

11. TROUBLESHOOTING                           *simplemarkdown-troubleshooting*

"daemon simplemarkdown-daemon not found"
    The backend has not been built.  Run `./install.sh` in the plugin
    directory, then |:SimpleMarkdownRestart|.

"Daemon speaks protocol vN, this plugin speaks vM"
    The Vim files were updated without the backend being rebuilt, which is
    what a plugin manager does by default.  The preview says so in the window
    rather than drawing a document laid out to a format it cannot read: run
    `./install.sh`, then |:SimpleMarkdownRestart|.

Tables and code frames are misaligned
    Your terminal renders East Asian Ambiguous width characters as double
    width.  Set >
        let g:simplemarkdown_style = 'ascii'
<   or configure the terminal to treat them as single width.

Nothing happens on :SimpleMarkdown
    The buffer's filetype is not in |g:simplemarkdown_filetypes| and its name
    does not look like Markdown.  Check with `:set filetype?`.

A setting seems to be ignored
    Run |:SimpleMarkdownHealth|.  A value of the wrong type, or a number
    outside its range, is corrected rather than obeyed, and the health report
    is where that is said; `:echo g:simplemarkdown_...` is not, because the
    variable was rewritten with the corrected value.  A misspelt option name
    is listed there too — nothing else can notice one, since nothing reads it.
    See |simplemarkdown-config-validation|.

A code block is not highlighted
    syntect does not bundle a definition for every language; `toml` and `vim`
    are two it lacks.  The code is still shown, just uncoloured.

The preview stops updating
    Run |:SimpleMarkdownHealth|.  If the crash-loop breaker is open, the
    backend died repeatedly; |:SimpleMarkdownLog| has the reason and
    |:SimpleMarkdownRestart| clears the breaker.

Editing a very large document does not live-update
    Above 20000 lines the preview stops re-rendering on every keystroke and
    updates on write and on |:SimpleMarkdownRefresh| instead.

"omd not found"
    The external preview needs a binary this plugin does not ship.  Run
    `cargo install omd`, or point |g:simplemarkdown_omd_path| at it.  The
    in-Vim preview does not need it and is unaffected.

The browser preview does not follow my typing
    By design: omd watches the file on disk, so it reloads on `:w`.  See
    |simplemarkdown-external-save|.

|:SimpleMarkdownHealth| says every render is full, none incremental
    Something is resetting the preview between renders — |:SimpleMarkdownLog|
    says which.  The two common causes are a window that keeps being resized
    (layout is width-specific, so those renders cannot be patches) and a
    document being rewritten wholesale rather than edited, where a patch would
    be no smaller than the document and the daemon sends the document.

DAEMON COMMAND LINE                                *simplemarkdown-daemon-cli*

The daemon takes no arguments in normal use: the plugin starts it and speaks
JSON over its stdin and stdout.  For diagnosis it also answers: >

  simplemarkdown-daemon --version
  simplemarkdown-daemon --help
  simplemarkdown-daemon --self-test
<
--self-test renders a fixture and checks the result and prints "ok".
install.sh runs it on the freshly built binary before replacing a working one,
so a build that compiles but does not work never reaches lib/.

Every daemon in the simple* suite answers these three the same way.  This one
adds four of its own: >

  simplemarkdown-daemon --classes
  simplemarkdown-daemon --codes
  simplemarkdown-daemon --preview FILE [WIDTH]
  simplemarkdown-daemon --bench FILE [WIDTH] [RUNS]
<
--classes lists every text-property class the renderer can emit and --codes
every diagnostic |:SimpleMarkdownLint| can report; `make check-classes` and
`make check-codes` prove that the Vim side registers all of the first and the
help documents all of the second.

--preview lays a file out on stdout, which is also what `make preview` uses to
review a layout change.  --bench times a first render, the steady-state
renders after it and the patch a one-word edit produces; `make bench` runs it
over the project's fixture.

VENDORED SUPERVISOR                                *simplemarkdown-simplecore*

The daemon supervisor in autoload/simplemarkdown/core.vim, and the test
harness beside it, are vendored from the suite's shared .simplecore bundle
rather than written here — each plugin carries its own copy so that
installing this plugin alone is enough.  Do not edit those files in place: >

  make core-verify
<
checks each of them against the sha256 recorded in .simplecore.manifest and
fails the build when one has drifted.  `make check` depends on it.

The bundle lives at https://github.com/beamiter/simplecore.  To change the
supervisor, clone it beside the plugins, edit it there, and re-vendor: >

  git clone https://github.com/beamiter/simplecore ../.simplecore
  ../.simplecore/vendor.sh
<
